# AI 刮削入库：电视剧匹配

版本 1.9.11 为电视剧增加独立的目录与季集匹配流程。电影继续使用原来的身份核验和长片筛选流程。

## 使用方法

AI 兜底解析默认接口为 `https://api.deepseek.com`，模型为 `deepseek-flash`，均可编辑或清空。API 密钥默认留空，填写后在插件设置中明文显示；关闭“启用 AI 兜底解析”时，接口、密钥和模型仍显示，但不可编辑，已有配置继续保留。

添加目录时可选择 **自动识别、电影、电视剧**。电视剧建议每部剧放在独立目录，目录中保留剧名和年份；分季时使用 `Season 01`、`S01`、`第一季` 等子目录。

支持的示例：

```text
电视剧/西游记.1986/01 猴王初问世.mkv
电视剧/示例剧.2020/Season 02/03.mkv
电视剧/示例剧.2020/S01E01.mkv
电视剧/示例剧.2020/S01E01-E04.mkv
电视剧/示例剧.2020/第十二集.mkv
电视剧/示例剧.2020/Specials/S00E01.mkv
```

单集名称只用于本地集标题提示，不作为剧名检索。普通电影目录中的编号电影不会仅因 `01` 前缀就被当作电视剧。旧目录继续按自动识别处理。

手动匹配优先提取剧目录的名称和年份，检索电视剧候选。在剧目录上手动确认剧名后，统一处理目录内的单集和附加内容；整部剧确认后，无法对应官方季集的内容留在所属季的正常集之后，标记为“未知集”。目录信息不足时可以输入剧名或 TMDb ID。

## 数据与准确性

- 同名候选必须结合年份核验。后续季可以使用该季首播年份，无法可靠区分时保留人工确认。
- 以整季为单位获取单集资料，并在一次扫描内共享剧级身份与季资料，避免每个文件重复请求。
- 不为本地内容伪造 TMDb 单集身份。剧目录确认后，编号缺失、越界、官方列表缺少对应集的文件以原文件名作为本地“未知集”收录；临时网络失败仍保留重试状态，避免覆盖已有的准确资料。
- 多集合并文件为每一集建立记录，所有记录指向同一个真实文件。它不是自动切割视频，也不生成集间播放时间标记。
- 只有源编号完整覆盖一整季、且能唯一核实偏移量时，才将续集的连续编号换算为该季集号；不完整的越界编号作为未知集保留。
- 明确标注的精编/剪辑版保留本地编号，不借用原版不同剪辑的单集剧情、首播日期或单集 ID。
- `Bonus`、番外、花絮、访谈、删减片段等附加内容保留在所属季的正常集之后，作为本地“未知集”展示；嵌套的附加内容目录向上归属剧目录，官方 Specials 仍支持第 0 季匹配。
- 未知集保留原文件名，按数字自然顺序排序；重新扫描仍保持自然顺序，已有文件的关联和观看状态保留。它们不借用其他正式单集的剧情、首播日期或 ID。
- 国产剧等多剧目录先展示剧目录与匹配统计；进入剧目录后查看单集。大列表每页最多 80 项。
- 所有插件菜单使用 Kodi 官方支持的离屏 ListItem 创建方式，完成后整批交给界面显示，避免构建列表时反复等待界面锁。
- 媒体源菜单、进度只展示目录名和协议，如 `国产剧[SMB]`；剧列表及剧内导航标题只显示剧名和年份，不附带协议。插件链接使用不含认证信息的路径标识，真实连接信息仅供后台使用。
- 同一单集的不同编码文件各自保留，不会覆盖另一文件的关联。Kodi 原生列表可能显示两条单集记录。
- 写入按文件进行事务提交，合并集要么全部完成、要么全部回滚。共享电影写锁，保留已有文件的添加时间、观看次数和续播书签。
- 剧级 ID 去重，单集保存真实 TMDb ID、评分、演员和剧照；图片缓存使用与数据库一致的图片尺寸。

## 开发验证

```sh
python3 scripts/test_tv_scanner.py
python3 scripts/test_tv_directory.py
python3 scripts/test_movie_scanner.py
```

测试使用脱敏路径、模拟网络响应和 Kodi 22 数据库表结构，不包含媒体文件、用户数据库或密钥。

“扫描媒体库文件”检查所有已添加目录的新增/删除文件；目录长按菜单中的同名入口仅检查当前目录。它们保留已匹配结果，新文件进入待匹配列表，识别刮削使用“扫描全部／扫描此目录”入口。停止扫描只在扫描或文件检查进行中显示；文件检查收到停止请求后完成当前目录，再停止后续目录。

文件列表中点击影片或单集会直接播放所选文件，未匹配的视频也可播放。电影条目保留“手动匹配”，电视剧在剧目录上统一匹配，单集无需手动匹配；保留 Kodi 的“添加收藏”，禁用列表条目的“由此连续播放”等自动排队入口。导航链接仍使用不含认证信息的路径标识，只有播放器解析阶段才读取真实地址。

目录级手动匹配会保存确认的剧身份，后续新发现的单集继承它；其他剧目录和电影的匹配结果保持独立。直接添加的单剧目录，也可在插件首页该目录的长按菜单中匹配。


1.9.9 的目录识别补充：

- 支持 `剧名S02.English.Title.年份`、`剧名.第二季` 和带发布标签的纯季目录；季号不再混入搜索名称。
- `Show.S01-S05.年份范围/季目录/单集` 统一归属剧合集目录，同时分别保留首播年份与季年份；不同季直接放在媒体根目录时保留各自的物理目录。
- 正常检索以目录为主；仅目录匹配失败时，才使用两集以上一致的英文剧名前缀补充检索。不会使用单集标题，不会覆盖已经核实成功的目录身份。媒体根目录里的独立单集直接从文件名提取剧名。
- 中文翻译与原始外文名称不一致时，保留 TMDb 官方英文检索结果中的译名，按同一个 TMDb ID 核验。
- 同名候选结合所属季、单集覆盖和整部剧集数核验；仍有多个同等候选时保留人工确认，不采用第一搜索结果。
- 待确认列表每个剧目录只显示一次，附带待处理视频数；一次确认应用到目录中的多季、单集和附加内容。电影仍逐文件确认。
- 电视剧源内没有季集证据的独立长片目录，只有在电视剧身份未核实且严格电影匹配通过时才按电影入库；单集、番外和网络失败不转为电影。
- 名称和目录解析使用有上限的内存缓存；目录展示只读取已保存的文件清单，不重新遍历媒体共享。

1.9.10：Bonus、花絮、番外、解说及未对应官方单集的内容保留在物理目录所属季，按自然顺序编号到正常本地集之后，不创建独立的附加内容季、不改名正常季。修正已入库条目时保留文件和单集 ID、观看次数与续播书签；仅清理已经没有单集的旧“未知集”季。

1.9.11：目录身份检索未核实或有同名歧义时，才提取 `S01E01` 等集号之前的英文剧名。至少两个不同单集的所有有效英文前缀必须一致；同一集的重复编码不增加证据，冲突名称不采用多数投票。回退后继续核验 TMDb 的官方名称、年份和季集资料。成功目录不增加回退网络请求，也不调用 AI。


1.9.12：将 TMDb 电影时长从分钟转换为 Kodi 媒体数据库要求的秒，修正影片时长和详情页剩余时间的计算基础。保存影片时继续保留观看次数、添加时间和续播书签。


1.9.13：稳定性审查修复。共享源不可达、子目录读取失败、扫描取消以及已有目录突然返回完全空清单时，保留旧的文件清单和入库记录；遍历限制目录深度。真正移除整个源仍通过显式移除目录操作。扫描历史采用唯一临时文件、刷盘及原子替换，损坏的现存记录不会被当成空库；保存失败明确中断并清理任务标记。

停止扫描及 Kodi 退出时检查取消，影片／剧集网络资料取得后写入前再次检查；失败等待可打断，已提交的晚到结果统一保存和计数。数据库 close 不再隐式提交未完成事务，成功写入仍显式提交。启动服务只在持有任务锁时清理残留标记。

图片缓存以线程数为上限提交活动任务，轮询取消；响应采用流式读取并限制 20 MiB，拒绝无尺寸的无效图片，写临时文件后原子替换。重缓存原位更新纹理 ID 及尺寸，避免 INSERT OR REPLACE 留下孤立 sizes 记录。后台预缓存也持有插件任务锁，与清库／扫描互斥，完成后关闭网络会话。TMDb 限流改为使用单调时钟和循环领取实际可用令牌，避免多个等待线程同时消耗同一令牌。网络和媒体路径日志脱敏，空媒体结果正常处理。


1.9.14：按物理文件统一清理电影和剧集。删除同一文件中的全部合并单集及对应元数据；电影默认文件消失时保留其他播放版本并将默认关联迁移到剩余版本，不删除其他源中的电影、单集和观看记录。清理整个源采用字面路径前缀，不将目录名中的 %／_ 当成 SQL 通配符。最后一集删除时清理空剧、季及季图片；蓝光目录按 INDEX.BDMV 数据库条目清理，无需访问片源。清理失败回滚并向上报告，扫描记录不会假装删除成功。

目录展示性能：已确认的电影不再参与电视剧目录和单集推断，减少混合源及大型电影目录的重复文件名解析，不改变未匹配资源和剧目录的识别规则。

自动任务在目录发现期间收到停止请求后不会再启动匹配阶段；扫描工作线程在写入前直接检查停止标记，不必等待控制线程更新取消事件。


## 独立界面（1.10.0）

插件改为 Python 脚本页面，不再作为 Kodi 视频文件夹。保持插件 ID 和用户配置、目录历史不变，`RunAddon(script.ai.movie.scanner)` 会直接打开独立窗口。

页面先显示，目录列表异步加载；首页使用已保存的目录和匹配信息，不访问媒体共享、不请求 TMDb、不重做整库季集分析。返回键由插件自己管理：启动时返回关闭窗口并丢弃迟到结果，子目录返回恢复上层列表和焦点，根页面返回调用前的页面。分页不积累返回层级。外部扫描更新可使当前页面缓存失效，不改变焦点对应的目录或文件。

添加目录、扫描、人工匹配、海报/演员缓存、清库、设置和单文件播放仍复用既有后台功能；长按菜单由独立窗口呈现。清库确认和任务互斥保持不变。已启动的后台任务不因退出浏览页面而自动取消，可使用停止扫描入口。

1.10.1：首页计数只统计已添加的媒体目录；无副标题的功能行单独垂直居中，与图标对齐。选中行使用皮肤的 `button_focus` 主题色。目录行保留匹配状态副标题。
